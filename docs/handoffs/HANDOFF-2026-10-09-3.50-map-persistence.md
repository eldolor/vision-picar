# Handoff 2026-10-09: 3.50 -- saving and reloading the map (decision document)

**Branch** `plan/3.50-map-persistence`. Section:
`docs/plans/ros-alignment/3.50-map-persistence.md`. No code.

**Why it exists.** Idea 4 (remember where things were seen, across
missions) needs a map frame that outlives a restart. Today it cannot:
`map_id` is `slam-<session>`, a random id per container start, and
3.46's inventory correctly refuses mixed `map_id`s.

**What the document contains.**

* Five options:
  * A: a fresh map every session (today);
  * B: reload and keep mapping (decided 2026-10-01);
  * C: localise against a frozen map;
  * D: localise by default, re-map on a trigger;
  * E: lifelong mode.
* A recommendation: D, starting from the dock, with versioned saves and
  a fall-back to a fresh map.
* Nine criteria, with thresholds, written before any build.

**Corrections found while researching.**

* Question 6 says deserialise offers "a whole-map localise". The pinned
  service does not; every mode needs the first node or a given pose.
* The bridge is at its route cap (13), so a save route would raise it.
  Saving at mission end avoids that.
* `RosWorld`'s ground-truth anchor (`start_truth`) is per session, so it
  must be saved with the map, or `/world/error` reads wrong after a
  reload.

**Not verified:** the slam_toolbox executables in
`vision-picar-ros:latest`. Docker could not be run from the isolated
worktree. List them first when building.

**Waiting on the user:** D or B; dock or last-pose start; the criteria's
numbers.
