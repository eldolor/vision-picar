# 3.107 Sections past 3.99 get their own ports; a shared ROS domain with an active section is warned about

*`PLAN-ros-alignment.md` section 3.107; index: [README.md](README.md).*

**Why.** `plan_section.py env` derives a section's live-stack resources
from its number, but takes the number modulo 100 (3.76 I8): 3.104 got 3.4's
ports and ROS domain, 3.106 got 3.6's (found 2026-10-26; neither ran a
stack). The ports need not wrap -- 9000 + 10 x N stays far below Linux's
ephemeral range (32768) for any section number this plan will reach. The
ROS domain must stay within 1-101 (higher ones overlap the ephemeral ports),
so past 3.99 some sharing is unavoidable; what can be done is to say so
when it matters: when another section with a live worktree on this machine
maps to the same domain. Asked by the user, 2026-10-26.

**Criteria (written before building; CLAUDE.md section 7):**

1. Ports never collide between any two sections 3.1-3.2000 and stay below
   32768; 3.1-3.99 keep exactly today's values (no live stack moves). Red
   on `dev` first.
2. The ROS domain is unchanged for every section (still 1-101, never 0, 73
   or 74), and `env` prints a shell comment naming each other section with
   a worktree here that shares it -- a comment, so `eval` still works.
3. The fast tier passes.

## Results (2026-10-26)

1. **Met.** `tests/test_plan_section.py::test_ports_past_3_99_do_not_wrap`,
   red on `dev`: ports unique for 3.1-3.2000, all below 32768, 3.1-3.99 at
