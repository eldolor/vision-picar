# 3.121 The push gate's suite in parallel (pytest-xdist), the same tests passing

*`PLAN-ros-alignment.md` section 3.121; index: [README.md](README.md).*

**Why.** The push gate's fast tier (`tools/plan_section.py` `run_tests`, run by
`ready` and the pre-push hook) is one pytest process on one core. On
2026-10-29 it took 31.6 and 30.9 min (3,492 passed) on this 12-core desktop,
and every session's push waits for it, again after any rebase. On
2026-10-30 the user took the recommendation: the suite in parallel first,
then explore's map fetch by version, then re-time goal choice.

**The change (written before building).**

* `pytest-xdist` joins `requirements.txt`, pinned.
* The fast tier runs as `-n <workers> --dist loadfile`: each test file stays
  whole on one worker, in its own order, so a module's fixtures and its
  tests' order are what they are today; only different files run side by
  side. Workers: `PICAR_TEST_WORKERS`, default chosen by criterion 2's
  measurement and never more than half the cores (the desktop stopped dead
  on 2026-10-28 under hours of full-CPU load; cause unproven).
* A file that cannot run beside others (a fixed port, a shared file, a
  timing bar that fails under load) is found by criterion 1, marked
  `serial` in a list beside `SLOW_FILES`, and run after the parallel pass
  in the same `ready`, one process, as today. A fixed bug in a test is fixed
  in the test, not hidden in the list.
* Without `xdist` importable (an old venv, the Jetson) the fast tier runs
  serially as today and says so in one line.
* Out of scope: `ready --full`, `tools/nightly_suite.sh` and the UI and
  live-stack tests (they stay serial); any test's own assertions.

**Criteria (written before building; CLAUDE.md section 7):**

1. **The same tests, the same results.** On one commit, the fast tier
   serially (today's command) and in parallel, each with `--junitxml`: the
   same set of test ids, each with the same outcome (passed, skipped,
   xfailed); 0 differences. Then three more parallel runs in a row: 0
   failures.
2. **Faster:** on a quiet desktop (load under 4 at the start, nothing else
   heavy), the median of those three parallel runs is at most 10 min,
   against the serial run timed beside it.
3. **The gate still gates:** a commit adding a failing fast-tier test is
   refused by `ready` and by the pre-push hook in parallel mode (a planted
   red test, in a throwaway branch, never pushed); with xdist absent, the
   fast tier runs serially and prints why; the gate's own tests pass.
4. **Heat:** the CPU package temperature (`~/temp-log`, 10 s samples) stays
   at or under 90 C through the four parallel runs.

## Results (2026-10-30): criteria 1-4 met

Measured on `420a6b4` (step A), the desktop quiet (load 0.7 at the start),
6 workers (half of 12 cores), `--dist loadfile`:

1. **Met.** The serial fast tier and three parallel runs, each with
   `--junitxml`: 3,519 test ids in every run, 0 ids added or lost, 0
   outcomes different (3,495 passed, 22 skipped, 2 xfailed each), 0
   failures in the three parallel runs in a row (and in a fourth,
   exploratory one before them). No file needed to run alone, so the
   `serial` list the design allowed for was not built: none is needed today.
   A file that later cannot run beside others is fixed in its test or, if
   it cannot be, gets that list then.
2. **Met.** Serial 1,056 s (17.6 min); parallel 211, 215 and 210 s:
   **median 3.5 min** (bar 10), 5.0x. (The two serial `ready` runs of
   2026-10-29 took ~31 min under another session's 10-worker job.)
3. **Met.** A planted failing test in a throwaway branch (never pushed,
   deleted): `ready` ends "suite failed: no pass recorded" and the
   pre-push hook's `gate` call "pre-push: fast tier failed", both exit 1,
   both running 1 failed / 3,495 passed in parallel. With an interpreter
   that has no xdist, `parallel_args` prints why and returns serial; the
   gate's own tests (`test_plan_section.py`, `test_review_376i.py`) pass.
4. **Met.** CPU package at most 67 C over the four parallel runs (bar 90);
   load at most 5.7 -- many fast-tier tests wait on sockets and threads
   rather than compute.

Reviews of `420a6b4`, `/code-review` (high) and the Thermos bug pass: no way
for a failing suite to pass the gate. Fixed in `472fc15`: the xdist probe
now runs where and as the suite runs, and names the plugin when
`PYTEST_DISABLE_PLUGIN_AUTOLOAD` is set (checked: `-p xdist.plugin -n 2`
runs); workers are half the usable cores by affinity (a container's limit,
not the host's), `PICAR_TEST_WORKERS` can only lower it and a bad value is
said aloud; the gate's own tests no longer assume xdist is installed (they
would have failed the gate on a venv without it); `worker_count`, not
`test_workers` (a name pytest could collect). Not acted on, as criterion 1
measures them and found none: timing bars beside busy neighbours, port
races between workers' `free_port()` calls, and files that read
process-wide state left by an earlier file on the same worker.

Other sessions: run `pip install -r requirements.txt` (pytest-xdist 3.8.0)
in the shared `.venv` -- this desktop's already has it; until then a venv
without it runs the tier serially, as before.
