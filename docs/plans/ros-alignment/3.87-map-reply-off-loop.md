# 3.87 The robot server's map reply, encoded off the event loop the wheel loop runs on

*`PLAN-ros-alignment.md` section 3.87; index: [README.md](README.md).*

**Why.** 3.81's G3 run (3.80.G's search on the board, 2026-10-16) found the
robot server's 20 Hz wheel loop late (a tick more than 100 ms after the
last, `robot/server.py`'s `late_ticks`) on 1,196 of 12,701 moving ticks,
max 0.364 s. 3.80.H split it (`3.80-tiered-identity.md`):

* `explore`'s `_note_seen` fetches `/world/map` on every tick; `tiered`
  never does (G1/G2: 0 late ticks with the same ROS container).
* `world_map()` is a sync route that returns a dict of ~10^5 cells. With
  no `response_model`, FastAPI (0.136 here, 0.142 on the board) runs
  `jsonable_encoder` on the return value **on the event loop**, where
  `wheel_loop()` and the watchdog run. Measured (H0): 131 ms for 72,000
  cells and 218 ms for 120,000 on the board at 15 W (30 / 47 ms on the
  laptop); `json.dumps` alone is 8.6 / 14 ms on the board.
* H1, dev's own plain `explore` (`c17c15c`) on the board with ROS, no VE,
  no perception loop: 75 late in its first 975 moving ticks. The cause
  predates 3.80.G; it is dev's, and so is this fix.

The watchdog loop shares that event loop, so the same stall delays a stop
for silence; the twin polls `/world/map` too.

**The fix.** `world_map()` returns its reply already encoded
(`JSONResponse`, built inside the route, so in the threadpool): FastAPI
passes a `Response` through without `jsonable_encoder`. The bytes are the
same encoding FastAPI's default response produces (Starlette's
`JSONResponse.render`). Nothing the safety layer vets, or when, changes.

**Criteria (written before building; CLAUDE.md section 7):**

1. **Red first:** a test drives `/world/map` with a 300,000-cell map while
   a probe on the server's event loop sleeps 5 ms at a time; the probe's
   largest gap is under 50 ms (the wheel loop's period). It fails on `dev`
   before the fix.
2. **The board, whole mission (3.37's bar):** dev's plain `explore` on
   the board under H1's conditions (`tools/jetson/headroom_mission.sh`,
   ROS, `home_first_floor`, cloud off, no VE, no perception loop),
   **0 late ticks**. Recorded beside it: `max_dt_s`, moving ticks, the
   mission's end and time (the progress half), MemAvailable.
3. **No silent change:** the reply's JSON is the same (a test compares it
   with FastAPI's default encoding); the suite passes unedited.
4. After merging `dev` into `plan/3.80-tiered-identity`, 3.80.H re-runs
   G3's configuration (VE resident) and judges it on the same bar.
