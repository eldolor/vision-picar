# 3.60 Inventory accuracy: the seven open review findings, verified, then fixed or recorded

*`PLAN-ros-alignment.md` section 3.60; index: [README.md](README.md).*

**Why.** 3.55 fixed the inventory's confirmed review defects and left seven
claims open (its section, "Sixth review" and "Not done"): one reproduced
by `/code-review` but not fixed (a later-frame join sums looks), six raised
by `/code-review` alone and never checked. CLAUDE.md section 6: a finding
only one reviewer raised is a claim to verify, not an order. Worked on
`dev` directly (the user, 2026-10-09). Numbered 3.60, not the next free
3.58: 3.56 and 3.57 were taken on `dev` while this was being written, by
sessions whose branches this cloud session cannot see, so the number
leaves a gap rather than race them.

The seven claims, as stated:

| # | Claim |
|---|---|
| 1 | Landmarks of one object counted separately in one frame and joined in a LATER frame sum their hits and votes, so a frame counts twice. |
| 2 | With no usable scan (`returns == []`), every landmark in view still takes a miss: `range_at` returns None, read as "not occluded". |
| 3 | A pending miss is cleared only by a hit from a NEW viewpoint; a re-sighting from near the last hit pose leaves it, so the next miss doubles. |
| 4 | Range is the NEAREST return in the 2-degree gate; `brain/arrival.py` moved to the median after the nearest placed a target on a door jamb. |
| 5 | `_absorb` drops the absorbed landmark's miss and viewpoint state (`_pending_miss`, `_miss_pose`, `_hit_pose`) on a later-frame merge. |
| 6 | Two extra sensor reads (`get_pose`, a 360-beam `get_scan`) per detecting frame on the tick path, not reused. |
| 7 | `scan_returns()` and `_wrap()` duplicate `robot/safety.py`'s `scan_points_cm()` and `brain/goal_pose.py`'s `_wrap()`. |

## Criteria (written before building or measuring; CLAUDE.md section 7)

1. **Every claim gets a verdict on evidence.** For 1-5: a unit test that
   reproduces the claimed behaviour on the code as merged in 3.55 (red
   against the claim's "should"), or a written reason it does not
   reproduce. For 6-7: the reads and the duplication counted from the
   code. Each verdict is REAL, NOT REAL or DESIGN (true, but a choice
   rather than a defect), recorded in the table below.
2. **Every REAL one is fixed with a test shown red without its fix**, or
   recorded as not fixed with the reason.
3. **No regression on 3.46's bars, judged on fresh missions.** The same
   sweep (`python -m tests.inventory_sweep --seed 3463`, 20 missions,
   detector errors on), run on `dev` before any change (baseline) and
   after: recall >= 90%, small >= 80%, placement median <= 0.20 m and
   p90 <= 0.50 m, duplicates <= 1.2, precision of reported >= 95%, and
   reported vs all >= 5 points apart. Seed 3463 is new: 3461 and 3462
   were used to tune and amend 3.46.
4. **Look counts are honest.** Over the same sweep, no landmark ever holds
   more hits than distinct frames that saw it (a frame-id count kept by
   the sweep, not by the inventory): **0 violations** after; the baseline
   count is recorded. A stability metric, paired with criterion 3's
   recall as the progress half.

## Review

`/code-review` and the Thermos bug pass (it writes stored data: risky,
CLAUDE.md section 6) on the branch.

`/code-review`, ten findings:

* **Fixed, each with a test red without it:** claim 2's rule was per
  frame, not per bearing -- a usable scan with no return at a detected
  mug's bearing still charged it a miss (an unplaced detection of the
  label within `GROUP_DEG` of a landmark's bearing now spares it); a
  later-frame merge could hold one frame as both a hit and a miss (a frame
  in `_looks` is dropped from `_missed`); claim 5's miss half had no test.
  `scan_returns()` keeps its old tolerance of a scan missing fields (the
  contract requires them; the old code tolerated it). The plan's results,
  a docstring's angle and the ENGINEERING spec's judged seed.
* **Not changed:** a RELABEL join (another label within 0.3 m) clearing a
  pending miss -- such a join is a vote and a look by 3.46's design, so it
  is a sighting of this landmark; `_LookCounter` re-walks every point each
  frame -- test instrument only, and the sweep's time is recorded below;
  `votes` rebuilt from `_looks` on each read -- the whole sweep ran in 142 s
  against the baseline's 163 s, so no cost shows at a house's scale.

`/code-review`'s fixes cost 1 point of precision (97.1 -> 96.1%, 103
reported, one more false). The bug pass found why, below; its fix brings
it back to 97.1%.

Thermos bug pass, four findings, no high or medium:

* **Fixed, red without it:** a same-label detection BEYOND `MAX_RANGE_M`
  also spared a miss, so a chair 4.5 m behind where a chair was kept the
  gone one reported -- the lidar had seen through its spot. Only a
  detection with no return at all spares a miss now
  (`test_a_far_detection_does_not_spare_a_miss_the_lidar_proves`).
* **Not changed:** after a merge `misses` can be odd (a frame one part
  missed and another part saw is a look, not a miss) while the score keeps
  the missed part's penalty if it was the larger -- both were true before
  the parts were known to be one object; small, and a merge never refunds
  or adds belief by design. A relabel join clearing a pending miss: the
  same finding as `/code-review`'s, the same answer. `hits_over_frames` is
  0 by construction now: kept as the regression guard it is.
