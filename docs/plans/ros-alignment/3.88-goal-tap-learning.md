# 3.88 Explore learns its goal choice from a person's taps

*`PLAN-ros-alignment.md` section 3.88; index: [README.md](README.md).*

**Why.** The user asked (2026-10-20) whether teleoperation can teach explore.
The answer agreed the same day, and recorded in the policy architecture
spec's open questions and 3.65's status:

* **What a person teaches is the choice, not the driving.** 3.65 phase 2
  learns only which of the candidates the rules allow explore sends next
  (`brain/goal_policy.py`, ten features a candidate). The example worth
  recording is a person's pick among those same candidates. D-pad verbs do
  not map onto "which candidate", and the driving stays nav2's (3.65,
  2026-10-11).
* **That is imitation, not RL.** A person gives examples, not a reward.
  Cloned picks are a warm start; 3.65's trainers can then carry on from it.
* **Corrections are goal taps, never takeovers (the user's decision,
  2026-10-20).** A person's Stop or D-pad still ends explore and latches
  the brain out (3.84, 3.76 C), unchanged. A tap is its own explicit
  message, not the person's map goal, which explore deliberately neither
  adopts nor cancels (3.76 E).

**What 3.65 left that this can change.** On 613 fresh houses the network
saved 11% of median goals (bar 20%), from ten geometric features that make
one frontier look much like another. This section asks whether expert
choices -- a privileged oracle's first, then a person's -- teach a better
ranking than a reward alone did, through the same features.

**Out of scope.** Learning on the car while it runs. New features (the room
prior is 3.80's "where to look" step 1; if it lands first, it is one more
input here, by amendment). Any change to sightings, approaches, escapes,
the retry book, the end of the search, nav2 or `robot/safety.py`.

## The phases

| Phase | What | Needs the user |
|---|---|---|
| **A** | Plumbing: explore can pause at a choice, a person's pick arrives as its own message, every choice is logged | No |
| **B** | A privileged oracle as the expert: cloning, then DAgger, in simulation | No |
| **C** | The person as the expert: the user taps in simulated houses; clone, warm-start, judge | Yes: about 2 h of the user's taps, asked for when A and B are done |
| **D** | The same on the Rover in the user's house | After the Rover; criteria written then |

**Why the oracle first.** It costs no one's time, it checks the whole
pipeline end to end, and it measures the ceiling: an oracle that knows
where the target is chooses as well as anyone can, so how much of its
advantage survives cloning through ten features says how much a person's
taps could ever give. If B's ceiling is under the bar, C is not asked for.

## Criteria, written before building (2026-10-20)

### A. Plumbing

1. **Ask mode.** A brain setting (default off) makes explore pause at each
   goal choice and publish the candidates it would rank: id, position,
   kind, features. A pick names a candidate id from the current list; a
   stale or unknown id is refused (409) and nothing is sent. No pick within
   60 s takes the rule's choice, logged as `rule_timeout`, never as a
   person's label. Time paused does not count toward
   `mission_time_limit_s`.
2. **Safety unchanged, pinned red-first.** A person's Stop or D-pad during
   a pause ends the mission and latches the brain out exactly as on `dev`
   (3.84's tests pass unchanged); a pick arriving after a Stop is refused
   and moves nothing; the robot is stopped throughout a pause (0 cm of
   motion, ground truth). A pick never offers or sends a candidate the
   rules exclude.
3. **The log.** One record a choice: mission id, house, step, every
   candidate's features, the pick and who made it (`rule`, `oracle`,
   `person`, `rule_timeout`). Durable writes, one file a mission, no image
   and no position outside the house frame. Rule mode with ask off logs
   nothing new and gives the same 100-house sweep (99 found, pinned).
4. **The twin.** The Sim tab draws the candidates on the map and a tap
   sends the pick; a phone-size screenshot as evidence, and a UI test that
   fails with the pick wired to the map-goal path.

### B. The oracle

The oracle sees ground truth: it picks the candidate with the shortest true
floor path to the target (ties: the rule's order). Houses as 3.65: training
from usable val 300-569, selection 100-199. **The final test is fresh
houses no section has used:** 600 usable houses from ProcTHOR-10K's `train`
split, imported by 3.66's checks (topology, furniture, usable) before any
model runs here. If the import fails a check, the fallback is the 613
`test` houses, used a second time, which is recorded.

5. **Cloning fits.** A linear ranking (softmax over the candidates, the
   ten weights) trained on oracle picks from the training houses agrees
   with the oracle's top choice on at least 60% of held-out choices
   (selection houses). Agreement with the rule's own pick is reported
   beside it, as the baseline.
6. **Cloning or DAgger beats the rule.** The best of three arms -- clone
   alone, DAgger (the learner drives, the oracle labels every choice it
   meets, 10 rounds), and clone then PPO (3.65's trainer, warm-started) --
   chosen on the selection houses, judged once on the fresh test houses:
   found >= the rule's found minus 1%, and median goals or median metres
   at least **20%** below the rule's (3.65's bar, unchanged). The oracle's
   own run on the same houses is reported as the ceiling.
7. **Live.** The winning arm, 3 missions on nav2 in `home_first_floor`:
   3/3 found, 0 chassis contacts, time to find within +20% of the rule.
   At laptop load under 4 (3.79's rule).
8. **Pinned in a test** that a regression fails.

If 6 fails, C is not asked for and the section ends with B's numbers.

### C. The person (asked for only if B passes)

9. **The taps.** The user taps through about 20 missions in training
   houses (about 2 h); Claude starts each mission and reads the logs. The
   data are the user's picks, at least 300 of them. Agreement of the
   user's picks with the rule's is reported first: above 80% means little
   to learn, and it is recorded either way.
10. **The bar.** Clone the user's picks (ten weights), then the same three
    arms as 6 with the user as the expert where the oracle was (DAgger
    rounds are capped by the user's time: one round of about 1 h).
    Judged once on fresh test houses not used by B: the same bar as 6,
    and the same live check as 7.

**What keeps it safe.** The same argument as 3.65: the policy only ranks
candidates the rules already allow, and a bad weight makes a search slower,
never a move unsafe. A pause stops the robot; it never moves it.

**Review.** A touches the mission loop with a pause and a call in flight,
writes stored data and adds a route: `/code-review` and the Thermos pass
(CLAUDE.md section 6).

**Cost.** No cloud call. Compute on the laptop CPU, as 3.65's trainers.
The `train` split download is free.
