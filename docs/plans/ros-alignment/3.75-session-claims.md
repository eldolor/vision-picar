# 3.75 Sessions claim discrete steps: a step table per section, live claims, guards at edit and commit

*`PLAN-ros-alignment.md` section 3.75; index: [README.md](README.md).*

**Why.** The user, 2026-10-12: "develop a mechanism such that each Claude
Code session works on discrete steps of the overall plan and that way they
are not stepping into one another." `docs/guides/PARALLEL-SESSIONS.md`
already gives each section its own number, branch, worktree, ports and
image, and a lock for heavy runs. Three things are missing. Asked "what is
next?" the same day, a session had to answer them by hand, from commit
times and CLAUDE.md prose:

1. **No list of discrete steps.** A section is often several steps (3.70:
   E1-E6, then 3.50's build, then S1-S5, M1-M5), and nothing records which
   are open, what each waits on (another step, the user, the Rover), or
   which files each will touch.
2. **No live owner.** A branch lives forever. Whether a session is still
   working on it was guessed from the time of its last commit.
3. **No guard while editing.** `overlap` reports a shared file only after
   both branches changed it (`robot/safety.py`, 2026-10-06/07).

## Design

* **Steps live in their section's file**, in a table under `## Steps`
  (rule 1 holds: a session edits only its own section's file). Columns:
  `Step` (`3.N.X`), `Title`, `Needs` (step ids), `Waits` (`user`, `rover`
  or `--`), `Touches` (repo paths; a trailing `/` is a directory, `*`
  globs), `State` (`open`, `done`, `dropped`).
* **The board reads every section file from the newest ref that has it**:
  its `plan/3.N-*` branch if one exists (the newest commit wins), else
  `origin/dev`. Committed text only; a step table is published by
  committing it.
* **A claim is a live lease, not a commit.** It is a file in the shared
  `.git` (`plan-claims/<step>.json`), which every worktree on this machine
  sees. It names the owning Claude Code process (the nearest `claude`
  ancestor, with its start time so a reused PID is not mistaken for it),
  the worktree and the branch. **A claim whose process has exited is free.**
  Nobody has to remember to release it. All claim changes take one `flock`.
* **A section with a branch but no table** is shown as one implicit step,
  touching the files its branch has changed. It is "active" if its branch
  committed within 2 hours, so sessions that started before this tool
  still count.
* **Three guards, in order of strength:**
  1. `claim` refuses a step whose `Needs` are not done, which waits on
     the user or the Rover, or whose `Touches` overlap a live claim or an
     active branch.
  2. A `PreToolUse` hook on `Edit`/`Write`/`NotebookEdit` **asks** the user
     before a session edits a path inside another session's live claim.
  3. A `pre-commit` hook **warns** (never blocks) when staged files fall
     inside another session's live claim. This catches edits made through
     Bash, which the edit hook cannot see.
* **A `SessionStart` hook** prints the board's short form, and what this
  session holds, into every local session's context.

Commands (`tools/plan_section.py`): `board`, `next`, `claim <step>`,
`release [<step>]`.

**Known limit:** claims are per machine. A session on the Jetson or in the
cloud does not share this `.git`. It still collides only at push, as
before.

## Criteria (written before building; CLAUDE.md section 7)

All are measured by `tests/test_plan_claims.py` (fast tier) unless stated.

1. **One winner.** 20 processes claim the same step at once, 50 trials:
   exactly 1 winner in **50 of 50**.
2. **A dead owner frees the claim.** A claim whose process has exited, or
   whose PID now belongs to a process with a different start time, is shown
   free and can be claimed. A live owner's claim is refused to anyone else,
   **every time**.
3. **Overlap is refused.** A step whose `Touches` overlap a live claim
   (same file, a file inside a claimed directory, or a glob match) is
   refused. A disjoint one is granted. Steps with unmet `Needs`, or waiting
   on `user` or `rover`, are refused.
4. **The edit guard.**
   * It asks on a path in another live claim.
   * It says nothing on the session's own claim or an unclaimed path.
   * It exits 0 with no output on malformed input.
   * p90 under **300 ms** over 20 calls on this repo, measured live.
5. **The commit guard warns and never blocks:** exit 0 in every case,
   with a warning naming the claim when one applies.
6. **The board on today's repo** (measured live, recorded here):
   * 3.65's and 3.74's branches show active;
   * `next` names a step no active branch touches.
7. **No change outside tooling and docs:** nothing in `robot/`, `brain/`,
   `control/`, `sim/`, `world/` or `service/`.
