# 3.47 Inventory review fixes: the stop-path race, double-counted looks, mission-id collisions, a local-only mode

*`PLAN-ros-alignment.md` section 3.47; index: [README.md](README.md).*

**Why.** 3.46 (the object inventory) merged without a code review. It was
the first change reviewed under CLAUDE.md section 6's new rule (2026-10-09):
`/code-review` plus the Thermos bug pass (`docs-review/THERMOS-BUG-PASS.md`),
since it touches the mission loop and writes stored data. Both reviewers
reported the first three defects below; the Thermos pass alone reported the
other two. Each was then confirmed against the code before fixing.

1. **A stop could skip the stop command.** `_observe` changed the
   inventory on the tick thread without `MissionRunner._lock`, while
   `_finish` read it under the lock. A new landmark joins the list one line
   before its first point, so a stop landing between the two made
   `summary()` divide by zero. `_finish` called `summary()` before
   `_safe_stop()`, so the exception skipped the stop, the policy's close,
   the end line and the save. (The robot watchdog, B3.1, still stopped the
   motors after 1 s.) The same race could fail `GET /mission/inventory`.
2. **One look could count twice.** A frame whose first detection gave
   landmark A its hit, and whose second matched B and folded A into it,
   left B taking the hit again: four hits from three looks, against
   `_absorb`'s rule that a merge never raises belief by itself.
3. **Two missions in one second shared a file.** The mission id was the
   time to the second plus the target, so a quick restart overwrote the
   first mission's local file and S3 key.
4. **No local-only mode.** `service/tunnel/run.sh` used
   `${INVENTORY_BUCKET:-lookup}`, which treats `INVENTORY_BUCKET=` as unset,
   so every run with AWS credentials uploaded the list of what is in the
   house.
5. **A cut-off save left a truncated file.** The save runs on a daemon
   thread; a brain exiting mid-write left half a JSON file.

**Criteria.** One per defect: a test that reproduces it, shown red with the
fix reverted and green with it, and the 3.46 suites still green.
**Recorded as a breach of CLAUDE.md section 7.1:** these were written with
the fixes, not before them -- the review of the fixes flagged it. The bar
is a reproduction rather than a measured threshold, which is why it was
missed; the next section with a measured criterion writes it first.

**Second round: the fixes reviewed** (`/code-review` and the Thermos bug
pass on the working tree; Thermos found all five fixes correct and
complete, with low findings only). Fixed, each test red without its fix:

- after an in-frame merge the landmark kept its old viewpoint, so the same
  look counted again next frame; the merge frame is now its last viewpoint
  and clears a pending miss (the merge test's extra frame);
- a landmark joins the list only with its first point -- the race's root
  cause, beside the lock (no test of its own: the race cannot be provoked
  on demand; the lock test covers the path);
- the save fsyncs before the rename and removes its temporary file on
  failure (the cut-off test, now a crash between write and rename);
- `INVENTORY_BUCKET=` now wins over a bucket in `config/robot.yaml`
  (`test_an_empty_bucket_variable_overrides_the_yaml`), so the opt-out
  does not rest on the yaml having none;
- the one-second test freezes the clock, so it is red with the old id on
  any machine; the run.sh test finds the file from its own path;
- `_finish` and `_observe` share one `_ended()` rule, and a frame that will
  be dropped costs no sensor reads.

Not changed: the lock is held only for `observe()`'s compute, measured by
the Thermos pass at 0.36 ms median and 1.5 ms max over a 150-step mission,
so the stop path does not wait on it in practice.

`tests/test_inventory.py`, `test_inventory_mission.py`,
`test_brain_server.py`, `test_mission_runner.py` and every test that loads
the brain config: 166 passed.

The frame dropped after the end is the narrow case: a frame before the
mission starts is still observed, as
`test_the_pose_is_read_with_the_frame_not_after_the_move` relies on.

**Third round** (`/code-review` on the second; each test red without its
fix):

- the in-frame merge fix over-corrected: when the surviving landmark had
  the larger score and this frame was a new view for it, `max()` dropped
  its look. It now gets the look once
  (`test_a_merge_never_loses_the_bigger_landmarks_own_look`);
- the second round's opt-out made a failed AWS lookup in `run.sh`, which
  exported an empty value, read as "local only" over a bucket in the
  yaml. A failed lookup now leaves the variable unset
  (`test_run_sh_a_failed_lookup_is_not_the_opt_out`);
- the save also fsyncs the directory after the rename, and a failing
  cleanup can no longer hide the real error; the cut-off test patches
  only the store's own fsync.

**Fourth round** (`/code-review` and the Thermos pass on the third; each
test red without its fix):

- the merge rule was still order-dependent: with the older, smaller
  landmark surviving, the larger one's look was lost (Thermos reproduced
  1.70 for 2.55). It is now one rule, `_count_look()`, computed for every
  landmark taking part before the merge
  (`test_a_merge_counts_the_look_once_in_the_other_order_too`); the
  earlier patches are gone;
- a save cut off by a crash leaves a `.tmp` no handler removes; the next
  save sweeps those over an hour old, never a fresh one that may be a
  save in progress (`test_a_crash_leftover_is_swept_but_a_save_in_progress_is_not`);
- the run.sh test passed on a block that crashed or took the wrong
  branch; it now needs a sentinel and a clean stderr (red on a malformed
  `[`);
- `inventory_report()` reads the outcome under the lock with the list;
  the dead `gmtime` patch is gone; the plain-host UI test uses its own
  host, so the env banner's same-origin `/health` cannot be judged in its
  place;
- the SessionStart hook sets the push gate and PATH before any network
  step, warns instead of stopping on a failed pip install, quotes its
  path and has a 900 s timeout.

**Fifth round** (`/code-review` and the Thermos pass on the fourth; the
Thermos pass fuzzed `_count_look()` -- 3,869 merge-free missions identical
to 3.46's rule, 16,182 reordered frames with order-independent scores --
and found no high or medium bug). Each test red without its fix:

- the score was right but `hits` and votes were not: two detections of one
  object placed 0.7 m apart each took a hit, and a third bridging them
  summed both, in some detection orders only. A frame now leaves one hit
  and one vote however its landmarks merge
  (`test_one_frame_is_one_hit_and_one_vote_even_when_it_bridges_itself`,
  three orders);
- the stale-tmp sweep judged age by the wall clock, so a clock jump at
  boot could delete a save in progress. This process's in-flight saves are
  now skipped by name, and a sweep can never fail a save
  (`test_a_save_in_progress_is_never_swept_even_if_it_looks_old`);
- `_absorb` takes the neighbour list `_count_look` found, so the landmarks
  scored and the landmarks merged are one list by construction;
- the SessionStart hook runs on startup and resume only (not on every
  compaction), and puts the venv on PATH only once it exists;
- the one-second test's docstring now says what it guarantees: red with
  the old id when the two starts share a second, nearly always;
- in-flight saves are keyed by full path, not file name; the hook also
  runs after `/clear`.

**Sixth review** (`/code-review` and the Thermos pass on the fifth; Thermos
fuzzed 4,000 missions: `hits` never negative, `sum(votes) == hits`, no
look lost; no high or medium bug from either). Left for 3.48, not fixed
here: landmarks of one object counted separately in one frame and joined
in a LATER frame still sum their hits and votes (`/code-review`
reproduced hits 3 from 2 frames; 65 such states in a 3,000-seed fuzz).
The score is right; the reported look counts and vote shares are
inflated. It is 3.46's `_absorb` summing rule, and the fix is a data
model change -- each landmark keeping the frames that gave it a look, so
`hits` and votes are a union on merge -- not a patch. Also left: the
match scan done twice per detection (efficiency), and a sweep racing a
save that starts during a backward clock step (microseconds, reported
as a save error, never silent).

**The flaky UI test that blocked the gate.**
`test_a_tunnelled_robot_gets_the_interstitial_bypass` failed 4 of 8 runs
here and 2 of 8 on `dev`: it connected to the real ngrok host, so the
health poll it captured existed only when the internet answered. The
tunnel is now played by the local server, the helper waits for the
request itself (5 s deadline) instead of a fixed 900 ms, and it captures
only the configured server's poll -- which also stops
`test_a_plain_host_is_left_alone` passing on an empty capture. 12 of 12
and 5 of 5 runs green; red with the ngrok header removed from `app.js`;
`tests/test_ui.py` in module order: 114 passed.
