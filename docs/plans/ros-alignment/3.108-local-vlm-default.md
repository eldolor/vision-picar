# 3.108 The local VLM on by default on the board

*`PLAN-ros-alignment.md` section 3.108; index: [README.md](README.md).*

**Why.** The user, 2026-10-26: "I want the local VLM on by default on the
board." Since 3.80.B, `picar-local-vlm` (Qwen2.5-VL-3B VE under TensorRT
Edge-LLM, `127.0.0.1:8005`) was installed and not enabled, and the brain
used it only with `tier_local_vlm_url` / `LOCAL_VLM_URL` set, which nothing
on the board set: the board's brain reported `tier_local_vlm: false`.

**The change.** On the board only (the laptop, the suite and the cloud have
no local VLM, so `config/robot.yaml`'s default stays empty):

* `tools/jetson/systemd/picar-stack.service` sets
  `LOCAL_VLM_URL=http://127.0.0.1:8005` and orders itself after
  `picar-local-vlm` (ordering only: a VLM that is down or killed leaves the
  stack up, and identity goes to the cloud tier, as 3.80 designed).
* `tools/jetson/install_services.sh` enables and starts `picar-local-vlm`
  with the other two units.
* `tools/jetson/README.md` section 5 says so; its update steps restart the
  VLM every time.

The benches already stop the VLM and put it back as they found it
(`headroom_identity.sh`, `headroom_mission.sh`, `bench_local_vlm.sh`), so
they measure the same with it enabled.

**Criteria (written before applying it on the board; CLAUDE.md section 7):**

1. **Enabled and up:** `picar-local-vlm`, `picar-stack` and `picar-ngrok`
   `enabled` and `active`; the VLM's `/health` answers on :8005.
2. **The brain uses it:** the brain's `/brain/health` reports
   `tier_local_vlm: true`.
3. **It answers:** one `/identity` request with a recorded frame returns a
   verdict within 3.0 s (`tier_local_timeout_s`).
4. **Memory:** with the VLM resident and the stack idle, `MemAvailable` is
   at least 1.0 GB (3.81's floor is 0.5 GB under load).
5. **The twin still works:** the deployed twin's `/brain/health` through
   the tunnel answers with the same `git_revision` as before.
