# 3.71 The robot server, brain and tunnel as Jetson services

*`PLAN-ros-alignment.md` section 3.71; index: [README.md](README.md).*

**Why.** On 2026-10-11 the deployed twin showed "Brain unreachable": the
robot server, brain and ngrok had been started by hand on the laptop, and
nothing brought them back when they stopped. The user then asked for them
to run on the Jetson, reachable over the internet, and to start at boot.
That was done the same day by hand (two systemd units, written on the
Jetson). This section puts those units, and how to install and update
them, in the repo -- the first half of B5 (`HARDWARE-READINESS.md`; its
second half, `mode: hardware` with the Rover attached, waits for the
Rover).

**Scope.** The units run `service/tunnel/run.sh` as it is (sim mode, the
twin's Sim tab) from a service worktree, `~/vision-picar-service`, so the
bench checkout `~/vision-picar` is never touched; and `ngrok start picar`.
No code changes.

**Criteria (written before building; CLAUDE.md section 7):**

1. **The repo is what runs:** `tools/jetson/install_services.sh` installs
   the units from `tools/jetson/systemd/`; afterwards the installed files
   are byte-identical to the repo's (`diff` empty).
2. **A crash comes back:** killing the robot server's process, the
   service is `active` again and `/health` answers through the public
   tunnel URL **within 30 s**.
3. **A reboot comes back, with no laptop:** after `sudo reboot` of the
   Jetson, both units are `active` and `/brain/health` answers through the
   public URL **within 180 s** of the reboot command; then one `frontier`
   mission started through the public URL (robot + brain both reached by
   the tunnel) ends with an outcome.
4. **The update procedure works:** the documented steps move the service
   worktree to a new `dev` commit, and `/health` through the tunnel reports
   that commit's `git_revision`.
