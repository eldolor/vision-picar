# 3.96 Explore's goal choice, learned again: richer features (rooms, indirect search) toward the oracle's ceiling

*`PLAN-ros-alignment.md` section 3.96; index: [README.md](README.md).*

**Why.** The user, 2026-10-23: "we need to revisit this again, add it to the
plan" -- the learned goal choice (3.65), which never became the default.
What is known:

* **3.65 phase 2:** the PPO network met every bar on its test set (-27%
  median goals) but on 613 fresh houses saved only 11% (bar 20%), while
  finding 2 more (608 vs 606). `explore_goal_policy` stays `rule`.
* **3.88 B:** the ceiling is far away. An oracle that knows the true floor
  path to the target needs a median of **3 goals against the rule's 9**
  (600 fresh houses). Cloning it through the same ten features agrees only
  29% (bar 60%), and as badly on its own training data (25.9%): the ten
  features **cannot tell the oracle's candidate from the others**. Clone
  then PPO cut goals 22% but found 590 vs 596. Its conclusion: "reopen with
  richer features, not more labels."
* **The ten features are all geometry** (path, turn, size, unknown share
  near the candidate, retries ...). None says which room a candidate opens
  onto, whether that room was already entered, or where this kind of
  object usually is. That last one is ASR's indirect search, which the user
  agreed to add as a candidate the same day; here it enters as a feature.

So this section adds features that carry the information the oracle uses,
measures first whether they can tell its pick apart, and only then trains.
Everything else in explore stays as 3.65 left it: only the choice among
candidates the rules already allow is learned.

**What the new features are** (computed in the brain from what it has; a
candidate's room comes from the map the brain sees, never from ground truth):

* **Room features:** whether the candidate lies in, or opens onto, a room
  explore has not entered; the share of that room still unknown; whether
  the candidate is through a doorway (3.70's `segment()` and doorways).
* **Indirect search (a prior):** how likely the target's kind of object is
  in the candidate's room type, learned once from the **training** houses'
  own object placements (ProcTHOR rooms carry a type and their objects).
  The room type comes from the brain's room labels (3.70's
  `brain/room_labels.py`); in the simulator they are the house's room names
  as the stand-in labeller, with an arm that drops labels (below).
* **Context:** how many candidates share the candidate's room (a cluster of
  frontiers in one unexplored room vs a lone sliver).

**Houses -- never mixed, as 3.65 and 3.88:**

* **Training:** ProcTHOR `val` usable 300-569 and `train` usable 0-299
  (the latter in 3.88's test pool, so it never tests again here).
* **Selection:** `val` usable 100-199.
* **Test, run once at the end:** **ProcTHOR `train` houses 1000-1999**, a
  new import no section has seen (3.66's import checks first). The rule,
  3.65's network and the new policy run on the same houses.

**Criteria (written before building; CLAUDE.md section 7):**

1. **The features carry the signal (step A, before any training).** A
   classifier trained on oracle picks in the training houses, using the
   old ten features plus the new ones, picks the oracle's candidate on
   **at least 50%** of held-out choices (selection houses), against the
   ten features' 29.1% on the same choices. If this fails, stop: no
   training run, the result recorded.
2. **Fewer goals, no fewer finds (the test houses):** found **>= the rule's
   minus 1%**, and median goals per found mission **>= 20% lower** than the
   rule, or median metres **>= 20% lower**. The same bar as 3.65 and 3.88,
   unchanged.
3. **Robust to missing room labels:** with the brain's room labels dropped
   at random on **50%** of rooms (on the car 3.70 S3 named 46 of 90
   rooms), criterion 2's found bar still holds and the goal saving is
   **>= 10%**.
4. **No house lost unexplained:** every test house the rule finds and the
   new policy does not is classified in this entry.
5. **Clean:** 100% of missions end with an outcome under the tick cap.
6. **Fast enough on the Jetson:** a whole goal choice (candidates,
   features, scoring) p90 **<= 100 ms** at 15 W on 3.65's six live maps
   (3.77's bar; the rule's is 90 ms).
7. **Live, on nav2:** behind `explore_goal_policy: <new name>` (default
   `rule`), three `explore` missions in `home_first_floor` on the live stack
   end `found`, with no more contacts than the rule and median time no more
   than 20% over it.
8. **The hand-drawn houses hold** with the flag on; with it off nothing
   changes. The test-house numbers are pinned in a test.

**Out of scope:** learning on the car; anything below the goal choice;
the found and arrival rules; turning explore into a behavior tree (its own
section -- the learned policy would be one leaf in it either way); cloud
calls (none are needed: room labels in the sim come from the house).

**Known confound, recorded before measuring:** 3.79 found that a slower
goal choice alone cut live goals 29 -> 22 with time unchanged. The sim
sweeps use `FakeNav` and are not affected; criterion 7's live goal counts
are read with that in mind, and time is its bar, not goals.
