# 3.61 Stop never forgets a mission a concurrent Start began

*`PLAN-ros-alignment.md` section 3.61; index: [README.md](README.md).*

**Why.** Recorded in 3.53 as a pre-existing race; the user approved fixing
it on 2026-10-09. `brain_server.stop_mission()` reads `state["task"]` at
entry, awaits (cancelling the old loop, then waiting for the old runner's
`finished`), and then sets `state["task"] = None` unconditionally. A Start
that lands during those awaits -- allowed, because the old runner is no
longer running -- installs a new runner and a new mission loop task, and the
Stop then erases that task. The brain no longer holds the loop it is
running: a later Stop cannot cancel it (a tick hung in that loop is never
cancelled, only the runner is stopped), and nothing else knows it exists.

**Checked before building, the other slots and the robot:**
* `state["runner"]`: never written by Stop. Safe.
* `state["reconfirm"]`: 3.53's claim (`_CLAIMED`) and the generation guard
  already cover a Start in between. Safe.
* **The stop command:** after its awaits Stop calls `runner.stop()` on the
  runner it captured. If a Start came in, that runner had already finished
  (a Start is refused while one runs), so `_finish` returns at once ("first
  outcome wins") and sends no robot stop. No stop can reach the new driver.
  The idle path (no runner) has no await before its stop.

**Criteria (written before building; CLAUDE.md section 7):**

1. **The new task survives.** A Stop held inside its awaits, a Start that
   lands meanwhile, then the Stop finishing: `state["task"]` is the new
   mission's loop task (0 of 1 runs clobbered; before the fix: 1 of 1).
   Driven concurrently over an async client.
2. **A later Stop reaches it.** After the race, a second Stop cancels that
   task (`task.cancelled()` or done) and ends the new mission `stopped`
   (progress pair: the new mission ran ticks before the second Stop).
3. **No stop reaches the new driver.** Between the Start and the second
   Stop, the robot receives 0 stop commands from the first Stop (a robot
   spy counts `stop()` calls).
4. **Unchanged otherwise.** 3.53's Stop tests (one late check per Stop, a
   Start during a Stop starts none for the old runner, a raising Stop
   releases its claim) and `tests/test_brain_server.py` pass unchanged;
   `ready` passes.

**Measured 2026-10-09** (`tests/test_stop_task_race.py`):

| # | criterion | measured | verdict |
|---|---|---|---|
| 1 | the new task survives | `state["task"]` is the new loop after the race (before the fix: `None`) | met |
| 2 | a later Stop reaches it | the second Stop cancels the new loop task | met |
| 3 | no stop to the new driver | 0 stops from the first Stop's runner during the race | met |
| 4 | unchanged otherwise | 3.53's Stop tests, `test_brain_server.py`, `test_failsafes.py`: 102 passed | met; `ready` at push |

**How the test reaches the window.** The first version parked the Stop in
`finished.wait` and passed on the unfixed code: the clear happens right
after `await task`, before that wait. The window is the `await task`
itself, while the old loop handles its cancellation; the test installs an
old loop whose cancellation takes a second (asynchronous cleanup) and lands
the Start inside it. It fails on the unfixed code. A first spy also counted
the NEW mission's own stops (its cloud is down, so it stops itself on each
vision failure) against the Stop; it now watches only the old runner, which
on the car shares the one robot.
