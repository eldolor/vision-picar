# 3.98 In the simulator an arrival is confirmed from geometry; the paid cloud call is opt-in

*`PLAN-ros-alignment.md` section 3.98; index: [README.md](README.md).*

**Why.** `docs-review/SPEC-REVIEW-3.md` fix 7, the simulator spec's open
question. A tiered mission on the Sim tab ended `found` only after one real,
paid cloud call on the raycaster's render, which ties a sim outcome to
whether a model recognises a flat-shaded billboard. 1.12 already has the
simulator report its detections from geometry rather than run a detector on
a render. **Decided by the user, 2026-10-24:** confirm a sim arrival from
geometry; keep the real cloud call as an opt-in for a run that means to test
it (the Stage 1 lit-renderer re-run). The car is unchanged.

**Design.** `brain.sim_arrival_confirm: geometry | cloud` (default
`geometry`, env `SIM_ARRIVAL_CONFIRM`). Only when the brain reads the robot's
frames as the simulator's (`_frames_are_simulated()`, the frame's
`metadata.source`, as 1.12's perception already does) does the tiered
policy get a geometry identity check: of the objects the arrival frame
reports (`detections`, the sim's ground truth) within `SIM_CONFIRM_CENTRE_DEG`
(10 deg) of the centre, the NEAREST must be the target. It answers in place
of the cloud call (`TieredVision.confirm_cloud`): no call, no cap, no
waiting on a call in flight, and `tier: "sim"`. A frame with no
`detections` is refused, never confirmed.

**Criteria (written before building; CLAUDE.md section 7):**

1. In process, a tiered sim mission built as the brain server builds it,
   with the default config and a cloud stub that fails if called at
   arrival: it ends `found` with 0 arrival calls; red on `dev` first.
2. An arrival at a different object (the target visible but not the
   nearest centred object) is refused, not confirmed; a frame with no
   detections is refused.
3. `sim_arrival_confirm: cloud` keeps today's path: one arrival call.
4. Frames that are not the simulator's (no `metadata.source: sim`) never
   use geometry, whatever the setting.
5. Offline (3.49): a sim tiered mission with every connection refused now
   ends `found` under `geometry`, and `arrived_unconfirmed` under `cloud`
   (3.49's recorded result is the `cloud` arm's).
6. Live: one tiered mission through the brain's HTTP API against the local
   plain-sim stack (no secrets, so no cloud) ends `found`, its status
   showing 0 cloud calls at arrival.
7. The tiered and arrival suites otherwise unchanged; tests that meant the
   cloud path at arrival set `sim_arrival_confirm: cloud` explicitly.

**Amendment 1 (2026-10-24, before the run it affects).** Criterion 6's
first run (`starter_house`, the default; `VISION_URL` a refused local port,
as 3.49's offline runs) ended `blocked` at step 289 without ever arriving
(arrival `approaching`, "target not detected"; 49 cloud calls refused,
48 of them cold search): with no cloud there is no search direction, and
the plain tiered search never saw the target. It says nothing about the
confirmation. The criterion is re-run on `SIM_MAP=scaled_house` (90 cm
doors, where nav2 is judged), same settings; if that also never arrives,
the run is recorded as not exercising the criterion and the in-process
mission (criterion 1) stands as its evidence.
