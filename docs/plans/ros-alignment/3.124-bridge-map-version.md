# 3.124 The bridge's map_version moves only when the grid changes

*`PLAN-ros-alignment.md` section 3.124; index: [README.md](README.md).*

**Why.** 3.123 put an ETag on `/world/map` keyed on `map_version`, but only
43% of explore's reads were 304s (bar 80%): the ROS bridge's `_on_map`
bumps `map_version` on every `/map` message, and slam_toolbox publishes one
a second (`map_update_interval: 1.0`) whether or not a cell changed. The
contract (`world/interface.py`) says `map_version` "bumps whenever `cells`
changes"; on the ROS path it bumps more often than that.

**Measured first (2026-10-30, `dev` 25f1e8e, `vision-picar-ros:latest`,
`home_first_floor`, explore, `found`):** polling the bridge's `/slam/map`
every 0.3 s for 900 s, 206 of 470 consecutive versions (44%) carried
exactly the previous version's grid and geometry. The mission's
`/world/map` reads were 338 of 851 304s (40%). Real changes come at
~0.29/s against ~1.7 reads/s, which predicts ~83% 304s once only real
changes bump the version (the same estimate gives 41% for `dev`, measured
40%).

**Change.** `_on_map` keeps the version when the new message's session,
resolution, size, origin and every cell equal the map it holds
(`picar_bridge/mapversion.py`, pure, no rclpy). It bumps when it holds no
map (`last_map` is cleared at every reload, fresh start and re-map) or
anything differs. `last_map` is still replaced whole (a new `at`), never
mutated.

**Criteria (written before building; CLAUDE.md section 7):**

1. Unit tests of `mapversion.next_version` (laptop, no ROS): an identical
   grid keeps the version; one changed cell, a changed size, resolution,
   origin (x, y or yaw) or session bumps it; no held map bumps it; versions
   never go down.
2. The bridge uses it: a test that `_on_map`'s source calls
   `mapversion.next_version` and no longer increments unconditionally.
3. Live, `home_first_floor`, explore, the branch image
   `vision-picar-ros:plan-3.124` (`PICAR_ROS_NETWORK=host`): at least 80%
   of the mission's `/world/map` replies are 304s, and the bridge poll
   finds 0 consecutive versions identical to the previous one. Progress
   half: the mission ends `found` with 0 contacts.
4. `ready` passes (the fast tier and the slow sweeps).
